# git

Everything git lives here, next to its config: the file mechanics, the
signing, the aliases, and the why behind the chosen defaults.

## The four files

| File | Role |
|---|---|
| `config` | the versioned config, portable as-is to any machine |
| `config.local` | the **machine-local** part: `gpg.ssh.allowedSignersFile` (always), plus `user.signingkey` and `commit.gpgsign` when a key is present, and `gpg.ssh.program` on macOS + Homebrew. Generated by `./run install gitsign`, gitignored, silently included when missing |
| `allowed_signers` | the signers accepted by `git log --show-signature` (ssh format) |
| `ignore` | global excludes, OS and editor junk only; project-specific patterns belong in each repo's `.gitignore` |

The config / config.local split is what keeps the repo portable: the key
and the `ssh-keygen` path differ per machine, so they have no business in a
versioned file.

`user.name` and `user.email` sit in `config`, versioned on purpose: one
person, several machines, one edit.

> [!IMPORTANT]
> They are coupled to `allowed_signers`, whose principal **is** that
> email. Change one without the other and verification stops matching,
> silently.

## Signing

Commits are ssh-signed (`gpg.format = ssh`) with a FIDO2 `sk-ssh-ed25519`
key (YubiKey). The `ssh-keygen` able to sign with these keys differs per
OS: Homebrew's on macOS (Apple's build cannot), the system one on Fedora
(native FIDO2). That is why `gpg.ssh.program` lives in `config.local`,
written by the gitsign step from what the machine actually has.

### Creating the keys (YubiKey)

<details>
<summary>The two credentials, flag by flag</summary>

Two distinct FIDO2 credentials live on the one YubiKey, one per job, so
revoking or rotating one never touches the other:

```sh
# 1. Commit signing, no touch required: a deliberate, accepted trade.
#    Given up: physical presence per signature. Accepted risk: malware on
#    an unlocked machine with the key plugged in can sign silently, and
#    verification can never tell (allowed_signers has no touch field).
#    Kept because signing fires on every commit and the AUTH key below
#    still demands a PIN: the stronger right keeps the stronger guard.
/opt/homebrew/opt/openssh/bin/ssh-keygen -t ed25519-sk -O resident \
  -O no-touch-required -O application=ssh:signing \
  -C "signing-yubikey" -f ~/.ssh/id_signing_sk

# 2. GitHub authentication, PIN required: pushing is a more powerful
#    right than signing, it costs a PIN.
/opt/homebrew/opt/openssh/bin/ssh-keygen -t ed25519-sk -O resident \
  -O verify-required -O application=ssh:github \
  -C "github-yubikey" -f ~/.ssh/github_sk
```

Flag by flag: the full Homebrew path because Apple's `ssh-keygen` cannot
create `sk-*` keys; `-O resident` stores the credential on the YubiKey
itself, so on a new machine `ssh-keygen -K` regenerates the key handles
with no file to transfer; `-O application=ssh:…` namespaces each
credential so both coexist on one key.

</details>

Wiring: upload `id_signing_sk.pub` to GitHub as a **signing key** and
`github_sk.pub` as an **authentication key** (two separate dropdowns),
then point ssh at the auth key:

```sshconfig
# ~/.ssh/config
# First, globally: brew's openssh (installed for FIDO2) shadows Apple's
# ssh and knows no UseKeychain, so IgnoreUnknown must precede any use.
IgnoreUnknown UseKeychain

Host github.com
  IdentityFile ~/.ssh/github_sk
  IdentitiesOnly yes
  # macOS ssh-agent has no security-key support and refuses to sign
  # ("agent refused operation"): bypass it, talk to the authenticator.
  AddKeysToAgent no
  IdentityAgent none
```

The signing side needs no manual wiring: `~/.ssh/id_signing_sk.pub` is
exactly the file the gitsign step looks for, and `./run install gitsign`
writes `user.signingkey` and `commit.gpgsign` into `config.local` on its
own.

### Checking that it works

```sh
git log --show-signature -1     # "Good \"git\" signature with …"
git verify-commit HEAD          # exit 0, or it tells you what is missing
```

A failure here is almost always one of three things: no
`allowedSignersFile` (regenerate `config.local` with `./run install
gitsign`), a principal that no longer matches `user.email`, or a commit
older than the key's validity window (see below).

### Rotating the signing key

`allowed_signers` is time-aware: git hands each commit's date to
`ssh-keygen -Y verify`, which checks it against the `valid-after` /
`valid-before` window of every line. Rotating therefore means keeping
**both** keys, each with its own window:

```text
me@example  namespaces="git",valid-before="20260804"  sk-ssh-ed25519@openssh.com AAAA…old
me@example  namespaces="git",valid-after="20260804"   sk-ssh-ed25519@openssh.com AAAA…new
```

Every commit is then verified by the key that was valid at its date. Drop
the old line and its commits stop verifying: the signature is still in
the object, but nothing can confirm it any more. Same on GitHub: unregister
the old public key and those commits fall back to Unverified.

> [!NOTE]
> That is exactly what happened here, and it is a **deliberate** choice, not
> an oversight. The July 2026 key was retired without a `valid-before` line,
> so the 32 commits it signed (19 here, 13 in the school repo, up to
> 2026-08-04) no longer verify, locally or on GitHub once the old public key
> is unregistered. Only one person ever wrote them, the current key is the
> only one in use, and carrying a retired credential forward to rescue eight
> days of history was judged not worth it. A branch ruleset requiring signed
> commits does not change this: it applies to what is pushed from now on, not
> retroactively to history already on the branch.

## Aliases

None here, on purpose: they are **shell** aliases (`gst`, not `git st`)
and live in `shell/aliases.sh`, see
[docs/usage.md](../../docs/usage.md). Accepted cost: they exist only
in interactive shells; scripts and tools call plain git.

## Notable defaults

| Setting | Why |
|---|---|
| `diff.algorithm = histogram` | better hunks than myers when blocks move |
| `merge.conflictStyle = zdiff3` | the conflict also shows the common base, not just both sides |
| `rerere` (+ autoupdate) | a conflict resolved once is replayed on later rebases |
| `pull.rebase` + `rebase.autoStash/autoSquash/updateRefs` | linear history; `updateRefs` moves stacked branches along |
| `push.autoSetupRemote` | first push without `-u` |
| `push.followTags` + `fetch.prune`/`pruneTags` | tags and refs in sync both ways |
| `transfer.fsckObjects` | object integrity checked on every transfer |
| `commit.verbose` | the diff below the commit message, in the editor |
| `help.autocorrect = prompt` | suggests the fix, never runs it on its own |
| `branch.sort` / `tag.sort` | recent branches first, version-sorted tags |
| `merge/diff.tool = editor` | follows `$EDITOR`, so you change the editor once and diff and merge follow; `trustExitCode = false`: an editor exit code says nothing about a merge |
